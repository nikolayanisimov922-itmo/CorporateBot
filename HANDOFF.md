Этот файл — для продолжения работы над проектом в новом чате Claude Code.

## 1. Что это
Корпоративный Telegram-бот **@IODesignbot** (компания Ivan Ogienko / IO Design).
Написан на Python (aiogram 3). Отвечает на вопросы по базе знаний через Claude,
принимает данные сотрудников в Google Sheets, делает рассылки, фиксирует
договорённости со встреч голосом. Работает 24/7 на сервере Hetzner.

Владелец/админ: Николай. Все ключи у него, он вставляет их сам.
Рабочий процесс: код пишется в чате Claude Code → пушится в GitHub → на сервере
`git pull` + перезапуск службы. Приложение Claude локально НЕ ставится.

## 4. Технологии
- Движок: **aiogram 3** (long polling, без вебхуков)
- Ответы ИИ: **Claude (Anthropic)**, эконом-модель `claude-haiku-4-5`
- Поиск (RAG): локальная модель **intfloat/multilingual-e5-small** (sentence-transformers),
  косинусный поиск на numpy. Индекс лежит в `data/` (gitignored).
- База знаний: **Notion API** (169 страниц), опубликованный сайт
  `mirror-psychology-ae8.notion.site` (для публичных ссылок всем).
- Данные: **Google Sheets** через сервисный аккаунт (gspread). Ключ —
  `google_credentials.json` (создан под ЛИЧНЫМ Gmail, т.к. рабочий Workspace
  блокирует создание ключей сервис-аккаунтов).
- Распознавание речи: локальный **faster-whisper** (модель `small`), нужен ffmpeg.

## 7. Функции бота (главное меню, двуязычное)
1. **📚 База знаний** — вопрос → поиск по Notion (RAG) → Claude отвечает строго по
   базе + публичная ссылка на страницу. Отвечает на языке пользователя (RU/EN).
2. **📤 Передать данные (план/факт расходов)** — только для команды из
   `TEAM` в app/expenses.py (4 комплектатора, 2 ПМ — по нику Telegram).
   Напоминания (время Дубая, UTC+4): комплектаторам — пн (план) и пт (факт)
   в 12:00 и 15:00; ПМ — 1-го и 2-го (план) и в предпоследний/последний день
   месяца (факт) в 12:00, в т.ч. в выходные. Повторное — только не приславшим.
   В напоминании кнопка → список «381-03 Название — сумма» (нужны номер, название
   и сумма, формат свободный; сумма 0 допустима; иначе отказ с объяснением) → бот показывает, как понял →
   «✅ Верно» → таблица. Простые строки разбирает код, свободный текст — Claude
   (только извлекает; проверку и числа делает код). Таблица: лист месяца
   «Ноябрь 2026» (слева комплектаторы по неделям, справа ПМ; в ячейке итог;
   исправление → новая сумма + заметка «было …») и «Ноябрь 2026 — детали»
   (все строки, ничего не стирается, старые помечаются «заменено»). Лист нового
   месяца создаётся 1-го числа. Руководителю НЕ пишем. Админу — если кто-то не
   нажал /start (бот не может написать первым) или запись не удалась.
   Админ (не в команде) проходит путь в тестовом режиме → лист «Тест».
   /team — кто подключён и кто сдал; /exp_test — прислать себе все напоминания.
   Состояние — data/expenses.json.
3. **🤝 Договорённости** — спрашивает «Какой проект?» (любой текст) → сотрудник
   записывает голосовое → faster-whisper распознаёт → Claude СТРОГО структурирует
   (без домыслов, на языке речи) → строка в таблицу «Договорённости»
   (Дата/Сотрудник/Проект/Расшифровка). Админу — короткое уведомление
   «Сотрудник оставил новую договорённость». Сотруднику — только «✅ Готово».
4. **📢 Рассылка** (только админ) — Общая (текст, уходит ВСЕМ, авто двуязычно
   RU+EN через перевод Claude), ПМ (пятница) и Комплектаторы (пятница) — готовый
   текст конкретным ID. Предпросмотр → подтверждение → отчёт доставлено/заблок.
5. **🔄 Обновить базу** (только админ) — перечитать Notion сейчас (+ показывает,
   сколько добавилось/изменилось/удалилось).
   Надёжность: если Claude не ответил — пишется расшифровка как есть + админу
   причина; если таблица недоступна — договорённость целиком уходит админу в
   личку с причиной (сотрудник видит «передано руководителю»); если упало
   распознавание — админу причина. Общий хелпер — app/notify.py (alert_admin).
5a. **⬛ Черный ящик** — фиксация проблем/кейсов команды. Отдел (кнопки, как в
   Google-форме) → рассказ голосовым ИЛИ текстом (что произошло, что сделано,
   выводы) → серьёзность (Критично/Средне/Незначительно, как в форме) → Claude
   СТРОГО оформляет «Что произошло / Выводы» (если Claude недоступен — пишется
   исходный текст) → строка в ОТДЕЛЬНЫЙ лист «Бот — Черный ящик» той же таблицы,
   куда пишет форма (лист «Ответы» бот не трогает, чтобы не мешать форме).
   Колонки: Отметка времени / Сотрудник (Telegram) / Ваш отдел / Серьёзность /
   Описание. Админу — уведомление «🔴 Критично · Отдел …».
6. **💰 Баланс** (только админ) — сколько осталось на Claude (подсчёт бота по
   токенам с момента последнего пополнения). После пополнения админ вводит сюда
   новый баланс в $. Уведомления админу в личку:
   - ⚠️ остаток ниже `CLAUDE_LOW_BALANCE_USD` (один раз до следующего пополнения);
   - 🔴 Claude отказал из-за денег (ошибка 402 / «credit balance too low»),
     не чаще раза в 3 часа;
   - 💳 раз в месяц (`HOSTING_REMINDER_DAY`, с 10:00) — напоминание, что Hetzner
     спишет оплату с карты. У Hetzner постоплата и нет API баланса, поэтому
     только напоминание. Состояние — `data/billing.json`.
   Точный баланс Claude обычным ключом API не узнать — отсюда ручной ввод.
6a. **📈 Управление** (руководители из `MGMT_IDS` + админ) — сводки по живым
   Google-таблицам, бот только ЧИТАЕТ их (доступ «Читатель»). Цифры по кнопкам
   считает код (0 токенов), ИИ — только в «💬 Спросить» (tool use: get_projects /
   get_workload / get_plan / get_hiring; модель — `MGMT_MODEL` или общая).
   - 📁 Проекты: сводка по статусам и отделам (лист «Общая таблица»), деньги
     (контракт/оплачено/остаток — листы отделов), загрузка по людям — тоже по листам
     отделов (листы «Загрузка …» НЕ используем, их формулы врут), новые подписания. Файл app/mgmt_projects.py.
   - 📊 Планы: листы «ПЛАН <МЕСЯЦ>», % = сумма фактов / план (колонке «% накоп.» не
     верим), 🟢🟡🔴 против темпа рабочих дней; бюджеты/стоимость лида — «в рамках /
     превышен». app/mgmt_plan.py.
   - 👥 HR: блоки недель × ролей в листах september/october…, парсинг по якорям
     (sources / названия этапов), Total и конверсии пересчитываем; синонимы ролей —
     ROLE_SYNONYMS в app/mgmt_hiring.py (уточнить у HR).
   - Кэш таблиц 5 мин (app/management_data.py), «🔄 Обновить» сбрасывает; доступ
     проверяется в каждом обработчике; кнопка в меню — через contextvar в
     app/keyboards.py (выставляет RegisterUserMiddleware).
   - Отдел и люди — по листам отделов (их ведут отделы; проект на листах двух
     отделов, напр. 387-03 — комплектация Alina + визуализации Ilya, идёт в зачёт обоим), сводка компании — по «Общей
     таблице»; пустой тип → отдел по коду (-02 дизайн, -03 комплектация, -04 ремонт).
     Деньги отдела — по проектам «In Progress» с листа отдела.
   - Планы (накопительно за месяц, без недель): колонки факта и % — по строке
     подписей НАД КАЖДЫМ отделом (у маркетинга «Факт | % накоп.» — D,H,L,P,T; у
     остальных «План | Факт | % нед | % накоп.» — факт E,I,M,Q,U, недельный план не
     трогаем). Главный маркер — итоговый % из последней колонки «% плана» (W),
     число = % × план (колонка C). Маркетинг — сумма фактов; стоимость лида — среднее.
     Где сумма фактов ≠ итоговому % — в /mgmt_check.
   - Админ: /mgmt_ping (видит ли бот таблицы и листы), /mgmt_check (что не заполнено),
     /mgmt_plan_raw [месяц] [отдел] — какие ячейки плана бот читает;
     /myid — для всех. Тексты — app/management_format.py.
7. **ℹ️ Помощь** — описание + контакт админа. **🌐 English / Русский** — язык.

## 9. Процесс рабочего дня / договорённостей (для людей)
Очная встреча с клиентом → сотрудник в тот же день открывает бота →
«🤝 Договорённости» → проект → голосовое → бот фиксирует в таблицу → админу
уведомление → админ публикует договорённости во внутренний чат проекта в Telegram,
тегает сотрудника → сотрудник перепроверяет → отправляет клиенту в WhatsApp-группу.
Админ следит за таблицей договорённостей. (Регламент Николай допишет отдельно.)
